# Caddy를 다루는 불변식

상태: **유효** · 처음 2026-10-03 · 정리 2026-10-14 (v1 시절 설계 부분은 지웠다 — git 기록에 있다)
관련: [v2 객체 설계](v2-objects.md) · [v2 계획](v2.md)

Naru는 Caddy를 화면 뒤의 엔진으로 쓴다. Caddy 설정은 Naru가 사이트 지도에서 통째로 그려 관리 소켓으로 밀어 넣고, 사람이 고칠 설정 파일은 없다.
아래는 그 방식이 깨지지 않으려고 **반드시 지키는 것**이다. 코드 주석의 "불변식 N"은 이 번호를 가리킨다.

---

## 1. 불변식

1. **관리 API는 유닉스 소켓으로만 연다.**
   TCP(`:2019`)로 열면 같은 네트워크의 **모든 앱 컨테이너가 웹서버 전체를 바꿀 수 있다** — 앱 하나가 다른 모든 주소와 인증서를 가로챌 수 있다.
   소켓은 Caddy와 Naru만 마운트하는 볼륨에 둔다. → `caddy.SocketSender`

2. **보내는 설정에는 늘 관리 소켓 설정이 들어 있다.**
   빠진 설정을 보내면 Caddy는 200으로 받아들이고 관리 API가 `localhost:2019`로 옮겨 간다. Naru는 즉시 제어를 잃고,
   그 설정이 autosave에 저장되므로 **Caddy를 다시 시작해도 돌아오지 못한다.** 트래픽은 계속 흐르니 겉보기엔 멀쩡하다.
   → 설정 쓰기가 늘 넣고, 보내기 직전에 `caddy.AdminSocketGuard`가 한 번 더 확인하고, 골든 테스트로 고정한다.

3. **`:80`과 `:443`은 서버를 나누고, HTTP→HTTPS 넘김은 Naru가 직접 그린다.**
   둘을 한 서버에 묶으면 Caddy가 넘김을 만들지 않고 HTTP로 그냥 서빙한다(실측). 나누고 `disable_redirects`를 켜면 Naru가 정한 대로만 넘긴다.

4. **쓸 수 있는 인증서가 있을 때만 HTTPS로 넘긴다.**
   발급이 아직이거나 실패한 주소를 넘기면 그 사이트는 열리지 않는다. 관리 주소라면 자기 서버에서 잠긴다.
   → 판단은 `siteMapBuilder` 한 곳 — `CertificateReader`가 읽은 인증서가 지금 그 주소를 덮을 때만 `RedirectHTTP`.
   설정 쓰기는 그 주소에만 `:80`에서 `307`을 그리고, **인증서 확인 경로(`/.well-known/acme-challenge/*`)는 넘기지 않는다** —
   IP 제한·점검 중·비밀번호 보호도 그 경로는 빼고 건다. 인증서 저장소를 읽지 못하면 "없음"으로 본다(넘김이 꺼질 뿐 HTTP로는 열린다).

5. **비밀은 Caddy 설정에 넣지 않는다.**
   설정은 `autosave.json`에 평문으로 남는다. git 토큰·웹훅 시크릿·환경 변수·알림 주소는 설정에 들어가지 않는다.
   **예외 하나:** 비밀번호 보호(기본 인증)는 Caddy가 직접 검사해야 해서 bcrypt **해시**를 넣는다. 원문은 어디에도 남지 않고, 화면·로그에는 해시도 나가지 않는다.

6. **Caddy 컨테이너 이름은 `shelf-`로 시작하지 않는다.**
   v1(Shelf)은 `shelf-`로 시작하는 컨테이너를 앱으로 본다. v1을 되돌릴 수 있는 동안(M7-5 전)만 의미가 있고, v1을 지우면 이 항목도 지운다.

## 2. 인증서

- **발급·갱신은 Caddy가 한다.** 사이트 지도에서 HTTPS를 켠 주소가 `:443` 서버에 있으면 Let's Encrypt(실패하면 ZeroSSL)로 받는다. 화면에 "갱신" 버튼은 없다.
- **Naru는 인증서 저장소를 읽기만 한다** (`caddy.CertificateFiles`). Caddy 관리 API는 발급된 인증서 목록을 주지 않기 때문이다.
  ```
  <저장소>/certificates/<발급자>/<주소>/<주소>.crt
    예: certificates/acme-v02.api.letsencrypt.org-directory/blog.example.com/blog.example.com.crt
        certificates/local/site.localhost/site.localhost.crt      ← 개발용 내부 CA (NARU_TLS=internal)
  ```
  읽은 것으로 주소마다 "쓸 수 있음 · 언제까지 · 발급자"를 보이고, 불변식 4의 판단에 쓴다.
- **곧 끝남**은 남은 기간이 수명의 1/6 미만일 때다 (90일짜리면 15일, 내부 CA 12시간짜리면 2시간). Caddy는 1/3이 남으면 갱신하므로 이 안으로 들어왔다면 갱신이 막힌 것이다.
- **하지 않는 것:** DNS 확인(와일드카드), 인증서 직접 올리기, 발급 실패 이유를 사람 말로 옮기기(실패는 Caddy 로그에만 있다).

## 부록 — 실제 Caddy로 확인한 것

Caddy v2.11.6.

| 확인한 것 | 결과 |
|---|---|
| 관리 API를 유닉스 소켓으로만 열기 | 소켓 생성, TCP 2019 연결 거부 |
| 다른 컨테이너에서 소켓으로 `POST /load` | 200, `GET /config/admin` → 소켓 주소 유지 |
| **관리 소켓 설정 없는 설정 적용** | 200으로 받아들임 → 즉시 제어 상실 → **재시작해도 회복 안 됨** (autosave에 저장됨) |
| `:80` · `:443` 한 서버로 묶기 | **넘김 안 됨** — HTTP로 그대로 200 |
| 서버 분리 + 직접 그린 넘김 | 경로·쿼리 보존 |
| 컨테이너 이름으로 프록시, Host 헤더 | 업스트림이 원래 Host를 받고, `X-Forwarded-For` · `X-Forwarded-Proto: https`가 붙는다 |
| HTTPS 프로토콜 | HTTP/2, UDP 443이 열려 있으면 HTTP/3 |
| 등록 안 된 주소 | 지정한 404 |
| 접근 로그 | JSON — `request.host`·`method`·`uri`·`status`·`duration`(초). `Authorization`·`Cookie`는 `REDACTED` |
| autosave 위치 | `/config/caddy/autosave.json` (`/data`가 아님 — 따로 마운트해야 함) |
| 내부 CA 인증서 수명 | 12시간 |
| Let's Encrypt HTTP 확인 (`:80` 서버 분리 상태) | 실서버 전환 때 주소 3개를 15초 안에 받음 (2026-10-10) |
| 웹소켓 (압축 → 프록시) | 설정 없이 됨 (101, 메시지 주고받기) |
| 웹소켓 + 설정 다시 보내기 | **같은 설정이면 안 끊김, 실제로 바뀌면 모든 웹소켓이 즉시 끊김.** 프록시에 `stream_close_delay`를 넣으면 유지됨 — 지금은 넣지 않았다 (2026-10-14 결정: 그대로 둔다) |
